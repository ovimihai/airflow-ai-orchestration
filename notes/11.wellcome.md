## Welcome

#### What You'll Learn

How to turn a business process into an AI-aware DAG: the tasks, the data passed between them, the branching, and the retries.

  

**The Problem**

  

Your manager describes a process in one sentence. Turning it into a DAG that runs reliably is where mistakes happen:

  

- Giving the AI task a vague job with no defined output

- Letting the model decide which task runs next

- Retrying AI tasks like any other task, ignoring cost and changing answers

  

**The Solution**

  

Design before you build. Fix the tasks, the contracts, the routes, and the retry rules up front.

  

Before: "AI, read the customer email and handle the cancellation"

  

After: Fetch Emails → Classify Intent (AI) → Validate Contract → Check Account → Route Case

  

The model returns a label.

Your code decides what runs next.

  

#### Module Structure

1. From Business Process to AI-Aware DAG

2. The XCom Contract for AI Tasks

3. Branching on AI Output

4. Retry Policies for AI Tasks

#### Keep in Mind

- Sketch tasks and dependencies before writing any code

- Every AI task needs a contract: known fields, allowed values

- The model returns a label; your code maps it to the next task

- An AI retry costs money and may return a different answer
